# Team and contributions

EmotionLab is a four-person course project. The role assignments identify responsibilities and defense topics. The degree of individual participation and authorship still require direct confirmation from members.

| Formal role | Evidence and discussion area |
| --- | --- |
| Project planning | Written requirement mapping, split constraints, stage plan and acceptance outcomes |
| Project design | Architecture and integration boundaries, product flow, model and visual rationale |
| Implementation and experiments | Model code, run logs and configs, experiment trade-offs, checkpoint reload and local inference |
| Acceptance and delivery | Test matrix, launch and recovery, report and demonstration evidence |

The implementation and experiments portfolio can be discussed from [training code](TRAINING_PIPELINE.md), [experiment decisions](EXPERIMENTS.md), [inference](ENSEMBLE_INFERENCE.md) and [acceptance](TESTING_AND_VALIDATION.md). Results and software belong to the team project. Individual claims need supporting actions and evidence. The T10 group meeting record still has blank sign-off fields.

AI tools assisted code drafting, documentation, design iterations and review. Team members are responsible for the parts they actually performed and for explaining methods and verification. [References and credits](REFERENCES.md)
